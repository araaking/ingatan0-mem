# Changelog

All notable changes to **Ingatan** are documented in this file.

The format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/), and this project adheres to [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

## [Unreleased] - 2026-11-23

General usability, search precision, and operational improvements based on real-world multi-project agent usage and a full codebase audit.

### Changed
- **Write-then-undo by default (no mandatory CLI approval)**: `remember` and `supersede` on `business` and `global` tiers now apply immediately (`require_approval = false` by default). Every write remains append-only logged and reversible via `ingatan diff` and `ingatan undo`, while `forget` on shared tiers remains CLI-only. The manual CLI proposal queue is still available via `require_approval = true` in `.ingatan.toml` / `~/.ingatan/config.toml` or `INGATAN_REQUIRE_APPROVAL=1`.
- **Optional `keywords` in `remember` with auto-extraction**: omitting `keywords` no longer fails the call; Ingatan automatically derives clean fallback keywords (stopword-filtered terms plus Indonesian affix-stripped roots from `stem_id`) from `text` and `entities` when none are provided.
- **Tighter, higher-precision conflict detection (`similar_facts`)**:
  - Filters out generic entities (business name, agent name, and high-frequency entities appearing in `>= 35%` of valid facts) and common agent/tooling boilerplate words (`Disimpan oleh asisten`, `Google Sheet`, `MCP`, etc.).
  - Eliminates top-50 FTS5 candidate starvation: every fact that mentions one of the new fact's entities is a candidate (found through the word index, up to 200 per file, those sharing topic words first), and no fact row is read only to be skipped.
  - Requires meaningful content-token overlap and adds a resource-ID guard so facts pointing to distinct external document/sheet IDs or URLs do not false-positive conflict. A similarity score never overrides this guard.
  - Skips re-opening pairs already recorded or previously resolved in `conflicts`.
- **More accurate & token-efficient `recall`**:
  - Strips Indonesian & English stopwords from query tokens and drops noise-only / weak tail hits on long queries instead of returning unrelated facts.
  - Replaces rank-based recency with a bounded freshness factor from a fact's age (the score of a `volatile` fact is multiplied by 0.98 to 1.02 with a 30-day half-life; a `stable` fact keeps its score), compares a weak tail hit with the best hit of its own index and file instead of comparing raw BM25 values across them, and adds an identifier phrase signal (e.g. `sync_report` matching `sync_report.py`) so newer logs do not outrank procedures and rules.
  - Reduces default document excerpts to `notes=2` (0 disables excerpts) and trims `NOTE_EXCERPT_CHARS` from `1200` to `400`, with relevance filtering on `notes`.
  - Condenses default fact metadata onto one line and adds `compact=true` mode for minimal token usage.
- **Stable-first cold-start ranking & stricter budget in `brief`**:
  - Prioritizes `kind="stable"` foundational facts ahead of newer `volatile` logs when `use_count == 0`, while preserving `use_count -> last_used` ordering once facts are recalled.
  - Tightens character trimming (`3.5` chars/token target) so Indonesian/mixed briefs stay reliably within `token_budget`.
- **Improved MCP tool ergonomics**: `remember` and `recall` descriptions now open with `"Remember..."` / `"Recall..."` for better tool discovery (`tool_search`) and encourage recording user aliases/nicknames in `keywords`.
- **Faster `remember` on large stores**: the repeat check is one lookup in the new `facts.text_key` index (migration `0003_fact_text_key.sql`) and the conflict check takes its candidates from the word index, instead of both reading every valid fact into Python (one counting pass over the `entities` column still runs inside SQLite, to find the entities too common to signal a conflict). On a synthetic store of 4,300 facts one `remember` took about 15 ms against 64 to 110 ms before (`scripts/bench_scale.py`, one laptop).
- **Semantic search is opt-in** (it was on by default on `main` for a short time): the default provider is `none` again, `fastembed` is no longer a dependency, and the local model needs the three packages of the `vector` extra (`numpy`, `onnxruntime`, `sentencepiece`) plus one `ingatan embeddings pull`. To keep using it after upgrading: set `[embeddings] provider = "local"`, pull the model, and run `ingatan reindex` (vectors of the previous default model are ignored unless you set `model = "intfloat/multilingual-e5-small"`).
- **Docs**: `README.md` and `docs/setup-hermes.md` now recommend `uv tool install --editable` for git checkouts and document write-then-undo, `~/.ingatan/config.toml`, and multi-business setup.

### Added
- **Optional semantic search (`[embeddings]`, off by default)**:
  - `provider = "none"` is the default: pure FTS5, no model, no extra packages, no network call. Opt in with `"local"` (offline), `"ollama"`, `"openai"` (any OpenAI-compatible endpoint) or `"gemini"`. Remote providers use stdlib `urllib`, and API keys travel in headers, never in a URL. Retrieval prefixes are applied for the E5 (`query:` / `passage:`) and EmbeddingGemma model families.
  - **Local provider on ONNX Runtime + SentencePiece** (`ingatan[vector]`: `numpy`, `onnxruntime`, `sentencepiece`): runs `xenova/multilingual-e5-small` (int8, the default) or `intfloat/multilingual-e5-small` (float32); local model names are matched without regard to case and stored lower-cased. One text per forward pass, CPU memory arena off, the model dropped after 5 idle minutes (`idle_unload_seconds`, `INGATAN_EMBED_IDLE_UNLOAD`) with glibc `malloc_trim(0)` on Linux, NumPy imported on first use with its BLAS capped at one thread. Measured on one Windows 11 laptop: a stdio server holds 275 MB with the model loaded and 79.5 MB without (`docs/RAM.md`).
  - **`ingatan embeddings pull [--model NAME]`** downloads the model files once, pinned to a repository revision and verified against SHA-256 sums (`HF_ENDPOINT` selects a mirror). It is the only command that downloads anything: the server never does and answers from FTS5 until the model is on disk.
  - **Cut-offs per model family** (`SimilarityProfile`): cosine scores are not comparable between models, so the recall floor and the conflict cut-off come from a measured profile (E5: 0.83 and 0.90) or from `[embeddings] recall_floor`, `conflict_similarity` and `conflict_strict_similarity`. A semantic conflict needs a shared specific entity: two facts on one template about different subjects score as high as a real update. `scripts/calibrate_embeddings.py` produces the numbers and `docs/EMBEDDINGS.md` records them, including what this small model does not do well.
  - **Diagnostics**: `ingatan doctor` probes the provider on one sentence (`--no-probe-embeddings` to skip), names the command that fixes a missing package or model file, and counts the valid facts visible to the configured agent that still need `ingatan reindex` (other agents' private facts are listed separately, with `ingatan reindex --agent NAME`). `ingatan reindex [--force]` backfills or refreshes vectors and exits non-zero with the root error when an embedding fails.
  - **HTTP mode lifecycle**: shares a single loaded embedding model across all businesses/agents in one process, hot-reloads per-scope config when `~/.ingatan/config.toml` changes, and evicts cached scope servers when tokens are revoked.
  - Vectors are L2-normalized `float32` BLOBs inside the existing SQLite files (`fact_embeddings` and `note_embeddings`, migration `0002_semantic_and_structure.sql`), fused into RRF alongside BM25, trigram, Indonesian root expansion and aliases, scrubbed on `forget`, and computed before any write lock is taken. An embedding failure of any kind falls back to pure FTS5.
- **Exact-repeat detection (`dedup=true` default on `remember`)**: a text that equals a valid stored fact of the same tier and category after ignoring case, spacing and trailing punctuation, with the same entities, refreshes `review_after`, `last_used` and metadata on that fact instead of creating a second row. A text that is only close in meaning is always saved and reported as similar: on the measured model a changed value ("Rp 15.000" to "Rp 18.000") scores higher than a paraphrase, so merging on similarity would drop the updates a memory exists to keep. Pass `dedup=false` to force a separate row.
- **Time-travel queries (`recall(..., as_of="YYYY-MM-DD")`)**: query facts that were valid at a specific historical point in time (returns facts superseded after `as_of`, excludes facts created after `as_of`, and does not mutate `use_count`).
- **Cognitive memory categories & pinning**: `remember` accepts `category` (`fact` | `rule` | `procedure` | `preference`) and `pinned=true`; `brief` prioritizes pinned facts and rules/procedures ahead of general logs, `recall` supports filtering by `category`, and CLI adds `ingatan pin <id>` / `ingatan unpin <id>`.
- **Project-scoped alias glossary (`aliases` table & `ingatan alias`)**: register local abbreviations or synonyms (`ingatan alias add LP "landing page"`) for automatic bidirectional query expansion during `recall`.
- **Lightweight relation edges (`edges` table & `ingatan link`/`unlink`)**: link complementary facts (`related_to`, `part_of`) via `remember(..., related_to=[...])` or CLI `ingatan link <src> <dst>`. Linked pairs suppress false-positive `possible conflict` warnings, resolve existing open conflicts between them, and surface 1-hop related facts in `recall` (`include_related=true` by default).
- **Global home configuration (`~/.ingatan/config.toml`)**: shared defaults (`default_agent`, `require_approval`, `[brief].token_budget`, `[embeddings]`, `allowed_businesses`) inherited by CLI, stdio MCP, and HTTP mode (`TokenStore.lookup`).
- **Opt-in multi-business MCP server mode**: set `INGATAN_BUSINESSES` (comma-separated) or `allowed_businesses = [...]` to serve multiple allowlisted businesses from a single MCP process (7 tools total, per-call `business` validated against the allowlist, still strictly isolated with zero cross-business search). Single-business mode remains unchanged with no `business` parameter in tool schemas.
- **Per-call `check_conflicts=false` on `remember`** for append-only daily logs and periodic snapshots.
- **Preserved original dates on `remember`**: accepts `source.date` (`YYYY-MM-DD`) and optional `valid_from` instead of always overwriting with today's date.
- **CLI upgrades**:
  - `--business` / `-b` flag on all CLI commands (and root `ingatan --business ...`) so you no longer need to `cd` into per-business folders.
  - `ingatan proposals approve --all` and multi-ID support with `[i/n]` progress output.
  - `ingatan conflicts list` and `ingatan conflicts scan [--dry-run]` to inspect or retroactively detect conflicts across existing facts.
  - `ingatan import <file.jsonl|json>` for bulk migration with original dates, auto-keywords, and optional `--scan-conflicts`.
  - `ingatan move <fact_id> --to <business>` to transfer misplaced facts cleanly between business databases.
- **Real-incident eval scenarios**: added 3 anonymized incident scenarios under `evals/scenarios/incidents/`, plus scenarios for a changed value, off-topic questions and a reworded replacement (46 scenarios in total: 45 pass and 1 is skipped without a model, 46 pass with one; 100% `recall@5`, 0% stale rate and 0% leak rate in both modes), and comprehensive regression tests in `tests/test_usage_improvements.py`.
- **Evals with a model**: `python -m evals --embeddings local` runs every scenario with the local model switched on and writes `evals/reports/latest-semantic.md`; `expect_none` asserts that a query returns nothing; a scenario with `needs = "embeddings"` is skipped without a model.
- **Measurement scripts**: `scripts/measure_embed_ram.py` (memory of the local model, step by step), `scripts/calibrate_embeddings.py` (score distributions behind the cut-offs) and `scripts/bench_scale.py` (`remember` and `recall` time against store size); `scripts/measure_ram.py` now records the embedding mode.
- **Deferred embedding on write (`[embeddings] defer = true`, off by default; `INGATAN_EMBED_DEFER`)**: `remember` saves a fact without calling the model and returns; a background thread of the server (stdio and HTTP) embeds the fact afterwards, stores the vector and runs the meaning-based conflict check that needed it. A conflict found this way shows as `possible conflict` in `recall` and in `ingatan conflicts list`, is counted by the conflict report, and has a log entry of its own (a new op, `conflict`, which `ingatan undo` can reverse and which never blocks undoing the fact's own entries). The trade-off: with `defer` on, the result of `remember` no longer lists a conflict that only the model can see; the word-based check is unchanged. `remember(check_conflicts=false)` is honoured later too. Facts the server finds without a vector for another reason are embedded as well, so no manual `ingatan reindex` is needed. A proposal (approval mode) is not deferred. A process with no server running (a CLI command) leaves the work queued in the database (new table `embed_queue`, migration `0004_embed_queue.sql`) for the next server start. `ingatan doctor` shows `defer: on` and says who will fill the missing vectors.
- **Shared model process (`[embeddings] shared = true`, off by default; `INGATAN_EMBED_SHARED`)**: one process per data folder holds the local model and every server asks it for vectors, instead of each stdio server loading its own copy. The first server that needs a vector starts it; `ingatan embeddings serve [--idle-seconds N]` runs it by hand and `ingatan embeddings stop` ends it. It listens on 127.0.0.1 only, records its port and a random token in `<data folder>/run/embed.json` (user-only, never fact text), must prove it holds the token before a caller sends any text, downloads nothing, and leaves after `idle_unload_seconds` without a request. A server that cannot reach it answers from the word index within a time limit: the tool call does not fail, and the model is not loaded into the server as a fallback. `ingatan doctor` reports whether the process runs. `scripts/measure_embed_ram.py --sessions N [--shared]` adds up the memory of N sessions alive together; no figure from it is published yet.
- **Measuring deferred embedding**: `scripts/bench_scale.py` takes `--embeddings local` and `--defer` (and prints what the fill cost per fact), and `python -m evals --embeddings local --defer` runs every scenario with facts saved first and embedded afterwards, writing `evals/reports/latest-semantic-defer.md`. Both need the model on disk; no figure from them is published yet.
- **Clean-install proof in CI**: the `clean-install` job now runs `ingatan setup` from the built wheel in an empty folder on Windows, macOS and Linux, then `scripts/smoke_round_trip.py`, which saves one fact, recalls it and forgets it (it refuses to run unless `INGATAN_HOME` is set). The README opens each language with the three commands of a new installation, and the install and semantic-search instructions use `setup` and `embeddings enable`.
- **`ingatan setup`**: a guided command for a new project. It asks for the business and agent names, whether to use semantic search (and runs the steps of `embeddings enable` if so), and which client to configure, then runs the `doctor` checks and exits non-zero when one fails. Every question has an option (`--business`, `--agent`, `--semantic/--no-semantic`, `--client claude-code|hermes|none`), so a script can run it with no terminal; a missing answer without a terminal is an error that names the option. For Claude Code it adds the server to the project's `.mcp.json`: the difference is shown first, nothing is written without a yes (`--yes` for scripts), other servers in the file are kept, and a second run changes nothing. For Hermes it prints the `mcp_servers` block to paste and writes no file. `ingatan init` is unchanged.
- **`ingatan embeddings enable`**: one command that switches the offline semantic search on. It stops before downloading anything when the packages of the `vector` extra are missing, downloads the model if it is not on disk, writes `provider = "local"` to `.ingatan.toml` (to `config.toml` of the data folder with `--global`, or when there is no project file) without touching the rest of that file, embeds the facts that already exist (`--no-reindex` skips this) and embeds one sentence as a check. It exits non-zero when an environment variable or another config file overrides the setting it wrote.
- **Release rehearsal and a tag guard**: the `Release` workflow can be started by hand to publish to TestPyPI (trusted publishing, environment `testpypi`), and a tag push now fails before building unless the tag equals `v<project.version>`. Publishing to PyPI still happens only on a tag push. The package metadata gained keywords and links to the changelog and documentation.

### Fixed
- **A vector can no longer outlive its fact**: `store_fact_embedding` writes only while the fact row exists. Before, a vector computed just before a `forget` could be stored just after it.
- **Stale/dangling conflicts on closed or expired facts**: `_in_open_conflict` now requires the partner fact to satisfy `is_valid_sql()`, so expired or superseded facts no longer leave active facts stuck in `possible conflict`.
- **`proposals.approve` conflict lifecycle**: approving a proposal now re-evaluates `similar_facts` against the live store (catching conflicts across batch-queued proposals), resolves open conflicts on a superseded target, and updates `ingatan conflicts` audit reporting accordingly.
- **Superseding a shared fact with an already-valid shared fact**: in `require_approval=true` mode, `supersede(old_business, existing_valid_business)` now queues a retire-only proposal (with full `audit.undo` support) instead of failing and forcing duplicate fact creation.
- **Cross-DB transaction atomicity in `confirm`**: wraps `ctx.business` and `conn` transactions together when confirming global facts.
- **`brief` no longer depends on random fact ids**: facts that tie on use, kind and date were ordered by their id, so which of them survived a tight `token_budget` differed between two stores holding the same facts (and the eval report's brief size changed from run to run). Ties are now settled by insertion order, newest first.
- **Markdown ingest directory filtering**: `ingest_path` now skips hidden and vendor directories (`.git`, `.venv`, `node_modules`, `__pycache__`) when recursing a folder.

## [0.1.0] - 2026-11-11

### Added
- Initial Ingatan MVP: local-first SQLite + FTS5 (BM25 + trigram + Indonesian affix-stripped root expansion + RRF) shared memory server over MCP stdio (`brief`, `recall`, `remember`, `supersede`, `confirm`, `forget`, `history`).
- Three-tier isolation (`global`, `business`, `agent`), per-fact `review_after` staleness tracking, secret redaction (`[redacted]`), content-scrubbing `forget` down to SQLite/WAL bytes, append-only audit log with `diff` and `undo`, and Markdown note ingestion.
- Claude Code hooks and Hermes Agent memory-provider plugin for episode capture and brief injection.
- HTTP mode (`ingatan serve --http`) with per-scope SHA-256 hashed bearer tokens (`ingatan token add/list/revoke`) and `SECURITY.md`.
- CLI tooling (`init`, `doctor`, `log`, `diff`, `undo`, `proposals`, `forget`, `ingest`, `conflicts`) and offline Indonesian eval harness (40 pattern scenarios).
